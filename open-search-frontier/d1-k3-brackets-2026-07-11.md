## Method

- **Construction.** The k-fold OR/co-normal power `G^{∨k}` exactly as `d1_ge_copies_sweep.py`'s
  `or_power_bitmask` defines it — tuples in `itertools.product` order, edge iff two tuples
  differ and are adjacent in the base graph in *at least one* coordinate. Rebuilt
  independently here with NumPy (`d1_k3_graphs.py`) for speed on the larger k=3 instances,
  with every base graph (C7, C9, Petersen, Paley(13)) validated against its known invariants
  (vertex count, regularity, exact edge count, and independently brute-forced k=1 clique
  number) before any product graph is built from it.
- **Vertex-transitivity reduction.** Every `G^{∨k}` here is vertex-transitive: if
  `φ_1,...,φ_k` are automorphisms of the base graph with `φ_i(u_i)=v_i`, then
  `(φ_1,...,φ_k)` is an automorphism of `G^{∨k}` taking tuple `u` to tuple `v` (direct check:
  `x~y` in `G^{∨k}` iff some coordinate is adjacent in `G`, which is automorphism-invariant
  coordinatewise). So **some** maximum clique contains vertex `(0,...,0)` WLOG, letting the
  entire search restrict to the induced subgraph on `N(0)`, plus 1. This is an exact
  reduction, not a heuristic — validated by running `--reduce` and non-`--reduce` side by
  side on every graph small enough to do both (all of k=1, k=2, and C9's k=3), always
  agreeing exactly (see transcript in "Validation" below).
- **Search.** Bitset branch-and-bound with a greedy-coloring upper bound per branch (the
  standard Tomita–Tanaka–Takahashi "MCQ" algorithm), implemented from scratch in C
  (`d1_k3_maxclique.c`, ~250 lines, no external libraries). This is a materially stronger
  pruning bound than the plain pivoting-Bron–Kerbosch-with-cardinality-bound approach the
  prior session's `d1_ge_copies_sweep.py` used (which is why, e.g., Paley13's 169-vertex
  k=2 case took >44s unfinished there but 0.02s here). Each run independently re-verifies
  its own witness clique against the RAW (unreduced, unrelabeled) adjacency bits, read fresh
  from the input file — a separate code path from the search itself.
- **Independent cross-check.** `d1_k3_verify_witnesses.py` re-derives all three base graphs'
  edge sets completely from scratch (a third time, in a separate script) and directly
  checks OR-adjacency for every pair in each reported witness clique — for C7, Petersen,
  and Paley13's lower-bound witness. All three pass.
- **No working background execution.** This sandbox's per-call container is torn down
  (its PID namespace killed, taking all children with it) when a tool call ends, regardless
  of `nohup`/`disown` — confirmed empirically (a `nohup`'d search was found dead a few
  seconds after being backgrounded, having made almost no progress). So there is no way to
  let a search run for, say, an hour unattended; all compute here is bounded, per-invocation,
  foreground, internally time-limited (`--timelimit`), and resumed — where resuming was
  needed at all (Paley(13) only) — via `--toplevel-lo/--toplevel-hi/--initial-best`, which
  restrict/seed the depth-0 branch loop so consecutive short invocations can carry a
  certified incumbent forward. This is explained in full in `d1_k3_maxclique.c`'s header.

## Results

| Graph | n | ω(G) | ω(G^{∨2}) | ω(G^{∨3}) | Search cost | Verdict |
|---|---|---|---|---|---|---|
| C7 | 7 | 2 | 4 | **8**, exact | 116,109 nodes, ~1s | PINNED |
| Petersen | 10 | 2 | 5 | **12**, exact | 10,754,445 nodes, 19s | PINNED |
| Paley(13) | 13 | 3 | 13 | **[33,46]**, not pinned | ~51.3M nodes across 8 sub-searches, ~4 min total | IMPROVED, not closed |

**C7 — closed.** `ω(C7^{∨3}) = 8` exactly (the search proves no 9-clique exists in the
218-vertex reduced graph; `toplevel_reached_break=1` confirms the color-bound terminated the
search naturally, not a timeout). This resolves the prior `{8,9}` bracket at the
literature-predicted value: load at `p=1/2` per event is `8·(1/2)³ = 1` exactly, margin 0 —
**NO ACTIVATION**, extending the k=2 zero-margin stall one copy further (`S₃=S₂=S₁=3.5`
exactly). C7 now matches C9's k=3 result via genuine brute force rather than the analytic
sandwich the prior note had to use for C9 (whose upper bound happened to be tight enough;
C7's is not — `9.393 ≥ 9` — which is exactly why C7 needed actual search). This is an
independent computational confirmation of Choudhary–Barbosa (arXiv:2411.09773) at n=7,
k=3, by exhaustive search rather than bound-sandwiching.

**Petersen — closed.** `ω(Petersen^{∨3}) = 12` exactly (no 13-clique exists in the
657-vertex reduced graph; again confirmed via the natural color-bound termination, not a
timeout). This is a substantive number — not the trivial lower bound `ω³=8`, not the
theta-ceiling `⌊2.5³⌋=15` — genuinely pinned by exhaustive search, closing the prior wide-open
`[8,15]` bracket. `S₃ = 10·12^(−1/3) ≈ 4.3679`, continuing the trend
`S₁=5 → S₂=2√5≈4.4721 → S₃≈4.3679`: monotonically approaching but still `≈0.368` above
`ϑ(Petersen)=4`. Unlike C7/C9 (complete stall from k=1), Petersen keeps making genuine,
if incomplete, progress through at least 3 copies.

**Paley(13) — improved, not closed.** The reduced graph (1854 vertices) is genuinely too
large to brute-force to completion with the compute realistically available in this
session: individual depth-0 branches (fixing just the first additional vertex beyond the
WLOG vertex 0) routinely explored 6–10 million search-tree nodes without finishing inside a
38-second budget. Sampling several slices of the depth-0 branch list (details below) raised
the certified lower bound from the trivial `ω(G)³=27` to an exactly-verified **33** — the
witness clique was independently re-checked in `d1_k3_verify_witnesses.py` against
freshly-rederived adjacency, a separate code path from the solver. The upper bound remains
the established theta-ceiling, **46** (`⌊(√13)³⌋`, from the prior note). This is reported
honestly as an **open, improved bracket** — Class A for the lower bound (exact witness),
Class B for the upper bound (closed-form ceiling), explicitly **not** Class A for the exact
clique number.

*What was actually checked, precisely* (this was opportunistic sampling, not a systematic
sweep, and does not certify completeness over any contiguous range): with incumbent seeded
at the best value found so far, depth-0 order-index ranges `[0,300]` and `[400,600]` each
resolved **instantly** (1 search node, color-bound proves nothing in that range can beat the
seed) — these two ranges are certified to contribute nothing above 32 and 33 respectively.
Ranges `[900,1100]`, `[1600,1749]`, `[1750,1852]`, and the single branch `{1853}` were each
searched for a full 38s without completing; `[1750,1852]` is where the improvement from 32
to 33 actually turned up. Ranges `(300,400)`, `(600,900)`, `(1100,1600)` were never probed at
all. Roughly 1000+ of the 1854 depth-0 branches remain both unproven-safe and
unexplored — resolving them exactly would need many more multi-minute-or-longer exact
sub-searches than was practical here.

**Why this doesn't matter for the actual convergence question, regardless of the exact
number.** Paley(13) already converges to `ϑ(13)=√13` **exactly** at k=2 (prior note,
Class A/B, a new instance of Cabello 2013's self-complementary vertex-transitive theorem).
Since `S_k ≥ ϑ(G)` for every finite k (for vertex-transitive `G`: the theta-ceiling argument
`ω(G^{∨k}) ≤ ϑ(Ḡ)^k` combined with `ϑ(G)ϑ(Ḡ)=n` gives this as a genuine per-k floor, not just
an asymptotic one), and `13^{3/2} = 13√13` is irrational, **no integer** `ω(Paley13^{∨3})`
can make `S₃` equal `ϑ(13)` exactly. So k=3 is analytically guaranteed to be (very slightly)
worse than k=2 here — `S₃ ∈ [3.628, 4.053]` for `ω∈[33,46]`, strictly above the `3.6056`
floor at either end — a fact that holds regardless of the still-unresolved exact clique
number. The exact value remains an interesting open combinatorial quantity in its own right,
just not one that changes the answer to "does k=3 help beyond k=2" for this graph (no, it
provably cannot, already established analytically in the prior note and reconfirmed here).

## Epistemic grading

- **C7^{∨3}=8, Petersen^{∨3}=12: Class A.** Exact exhaustive search (not a bound sandwich),
  cross-validated three independent ways: (i) against all nine previously-established k≤2
  (and C9's analytically-derived k=3) values before being trusted on new cases; (ii) an
  internal, same-program-different-code-path raw-adjacency re-check of the witness; (iii) a
  from-scratch, separate-script, separate-derivation Python re-verification
  (`d1_k3_verify_witnesses.py`) of the witness cliques.
- **Paley13^{∨3} ∈ [33,46]:** lower bound **Class A** (exact, independently re-verified
  33-clique witness); upper bound **Class B** (the project's own established closed-form
  theta-ceiling method, not brute-forced here). The exact clique number is **not resolved**
  — reported as an open, tightened bracket, not a determinate finding.
- **The k=2-vs-k=3 convergence non-improvement for Paley(13)** (previous paragraph): **Class
  A/B**, an exact analytic consequence of already-established facts (the theta-ceiling floor
  argument plus `13^{3/2}` being irrational), independent of the unresolved exact integer.
- The general open problem (Cabello, arXiv:1210.2988) is untouched by any of this, as
  ever — this is numerics on three more brackets of the identical-copies GE-with-copies
  sub-question, nothing more.

### Paley(13): certified lower bound improved from 33 to 39 — bracket now **[39, 46]**

The "trivial lower bound" quoted above (ω(G)³ = 27) undersells what was already proven in
this very note: cliques multiply across the OR/co-normal product (if C₁ is a clique of G^{∨2}
and C₂ a clique of G, then C₁×C₂ is a clique of G^{∨3} — any two distinct tuples differ in a
coordinate whose entries are distinct members of a clique, hence adjacent). With
ω(Paley13^{∨2}) = 13 (exact, table above) and ω(Paley13) = 3:

**ω(Paley13^{∨3}) ≥ 13 · 3 = 39**, strictly better than the search-found 33.

Explicit witness: {(a,b,c) : (a,b) in the solver's exact 13-clique of Paley13^{∨2},
c ∈ {0,1,4}} (39 tuples; {0,1,4} is a base triangle, differences 1, 4, 3 all QRs mod 13).
Verified twice, independently: (i) tuple-level OR-adjacency against a freshly re-derived
Paley(13) edge set, all C(39,2) = 741 pairs; (ii) directly against the packed binary
`bin/Paley13_k3.bin` the solver reads. Class A.

The exact value remains **open**. Evidence gathered on 2026-07-13 (~30 min solver budget):

- Exact seeded search (`--initial-best 39`): 171M nodes across two runs (5 + 10 min)
  completed only the hardest top-level branch, no 40-clique found. A greedy-coloring
  analysis of the reduced 1854-vertex graph (115 colors) shows a seed-39 proof must
  resolve exactly the 1000 top-level branches of color ≥ 39 (order-indices 854–1853).
- igraph's exact solver: timed out (3 min) on the full 2197-vertex graph.
- The pentagram-layer reduction does not apply (no C5 factor; see
  `d1-numerics-sweep-2026-07-11.md`, which already noted a generalization would be bespoke).
- SAT (pysat/CaDiCaL 1.5.3, sequential-counter cardinality ≥ 39 over the reduced graph,
  ~475k clauses): no result within a ~12 min wall box (the solve also proved
  non-interruptible from Python once started); terminated, inconclusive.
- Heuristic: 5,496 multistart greedy + plateau-swap restarts found many 39-cliques, never
  a 40th vertex.

All evidence is consistent with **ω(Paley13^{∨3}) = 39 exactly**, i.e. `S₃ = 13/39^{1/3} ≈
3.8334` vs the k=2 optimum `√13 ≈ 3.6056` — but this is NOT certified; the bracket stands
at **[39, 46]** (lower Class A, upper Class B theta-ceiling ⌊13^{3/2}⌋ = ⌊46.872⌋ = 46).
The convergence conclusion is unchanged and remains analytically forced: no integer ω can
make S₃ = √13, so k=3 provably cannot beat k=2 for Paley(13) regardless of the exact value
(section above). Closing the bracket exactly is estimated at ~20–40 single-thread CPU-hours
with this note's own solver (embarrassingly parallel over the 1000 hard top-level chunks
via `--toplevel-lo/hi --initial-best 39`).
